# Task Manager — SQLAlchemy ORM + Alembic

A hands-on Python project for learning **SQLAlchemy ORM** and **Alembic database migrations** using SQLite.

The project covers:

- SQLAlchemy engine and sessions
- Declarative ORM models
- CRUD operations
- SQLAlchemy `select()` queries
- Filtering with `where()`
- `AND` / `OR` conditions
- `IN` queries
- Ordering and limiting results
- Alembic migrations
- Autogenerated migrations
- Migration upgrades and downgrades
- Migration history and database version tracking

# 2. SQLAlchemy Database Setup

`app/database.py` contains the database configuration.

```python
from sqlalchemy import create_engine
from sqlalchemy.orm import DeclarativeBase, sessionmaker


DATABASE_URL = "sqlite:///./tasks.db"


engine = create_engine(
    DATABASE_URL,
    echo=True
)


SessionLocal = sessionmaker(
    bind=engine,
    autoflush=False,
    autocommit=False
)


class Base(DeclarativeBase):
    pass
```

## Important concepts

### Engine

```python
engine = create_engine(DATABASE_URL)
```

The engine manages communication between SQLAlchemy and the database.

### Session

```python
SessionLocal = sessionmaker(bind=engine)
```

A session represents a working unit with the database.

Example:

```python
session = SessionLocal()

# database operations

session.commit()

session.close()
```

### Base

```python
class Base(DeclarativeBase):
    pass
```

ORM models inherit from `Base`.

# 3. SQLAlchemy ORM Model

`app/models.py`:

```python
from sqlalchemy import String
from sqlalchemy.orm import Mapped, mapped_column

from .database import Base


class User(Base):

    __tablename__ = "users"

    id: Mapped[int] = mapped_column(
        primary_key=True
    )

    name: Mapped[str] = mapped_column(
        String(100)
    )

    age: Mapped[int] = mapped_column()

    email: Mapped[str] = mapped_column(
        String(255),
        unique=True
    )
```

This Python class represents the database table:

```text
users
├── id
├── name
├── age
└── email
```

The ORM maps:

```text
Python class  → Database table
Python object → Database row
Class field   → Database column
```

# 4. ORM CRUD

## Create

Create a Python ORM object:

```python
user = User(
    name="Ankit",
    age=30,
    email="ankit@example.com"
)
```

Add it to the session:

```python
session.add(user)
```

Commit:

```python
session.commit()
```

SQLAlchemy generates an `INSERT`.

Conceptually:

```text
User object
    ↓
session.add()
    ↓
session.commit()
    ↓
INSERT
```

# 5. Insert Multiple Objects

Use `add_all()`:

```python
users = [
    User(
        name="Rahul",
        age=28,
        email="rahul@example.com"
    ),
    User(
        name="Priya",
        age=32,
        email="priya@example.com"
    ),
    User(
        name="Amit",
        age=25,
        email="amit@example.com"
    )
]

session.add_all(users)

session.commit()
```

Difference:

```python
session.add(user)
```

adds one object.

```python
session.add_all(users)
```

adds multiple objects.

# 6. Read

SQLAlchemy 2.x style uses `select()`.

```python
from sqlalchemy import select

stmt = select(User)

result = session.execute(stmt)

users = result.scalars().all()
```

Then:

```python
for user in users:
    print(
        user.id,
        user.name,
        user.age,
        user.email
    )
```

Equivalent SQL:

```sql
SELECT id, name, age, email
FROM users;
```

---

# 7. Filtering

Use `where()`.

```python
stmt = select(User).where(
    User.age > 30
)
```

Equivalent SQL:

```sql
SELECT ...
FROM users
WHERE age > 30;
```

SQLAlchemy converts Python expressions into SQL expressions.

---

# 8. AND Conditions

Multiple conditions passed to `where()` are combined with `AND`.

```python
stmt = select(User).where(
    User.age > 25,
    User.age < 32
)
```

Equivalent SQL:

```sql
WHERE age > 25
AND age < 32
```

---

# 9. OR Conditions

Use `or_()`:

```python
from sqlalchemy import or_

stmt = select(User).where(
    or_(
        User.age < 28,
        User.age > 31
    )
)
```

Equivalent SQL:

```sql
WHERE age < 28
OR age > 31
```

---

# 10. IN

Use `.in_()`:

```python
stmt = select(User).where(
    User.age.in_([25, 30, 32])
)
```

Equivalent SQL:

```sql
WHERE age IN (25, 30, 32)
```

# 11. ORDER BY

Ascending:

```python
stmt = select(User).order_by(
    User.age
)
```

Equivalent:

```sql
ORDER BY age ASC
```

Descending:

```python
stmt = select(User).order_by(
    User.age.desc()
)
```

Equivalent:

```sql
ORDER BY age DESC
```

# 12. LIMIT

Get only two records:

```python
stmt = select(User).limit(2)
```

Combine with ordering:

```python
stmt = (
    select(User)
    .order_by(User.age.desc())
    .limit(2)
)
```

Equivalent SQL:

```sql
ORDER BY age DESC
LIMIT 2;
```

This pattern is the foundation for API pagination.

# 13. Alembic

Alembic is the database migration tool used with SQLAlchemy.

SQLAlchemy defines the desired database model.

Alembic manages changes to the actual database schema.

Think:

```text
SQLAlchemy Model
       │
       ▼
Base.metadata
       │
       ▼
Alembic compares
       │
       ▼
Database schema
       │
       ▼
Migration
```

# 21. Add a Column Using Alembic

We changed the SQLAlchemy model:

```python
age: Mapped[int] = mapped_column()
```

Then generated a migration:

```bash
alembic revision --autogenerate -m "add age to users"
```

Alembic detected:

```text
Detected added column 'users.age'
```

Generated migration:

```python
def upgrade():
    op.add_column(
        'users',
        sa.Column(
            'age',
            sa.Integer(),
            nullable=False
        )
    )
```

The reverse migration:

```python
def downgrade():
    op.drop_column(
        'users',
        'age'
    )
```

---

# 22. Migration Chain

After the second migration:

```text
<base>
   │
   ▼
75285f4cf385
create users table
   │
   ▼
542f727d8ac1
add age to users
   │
   ▼
HEAD
```

Each migration points to its parent using:

```python
down_revision = "75285f4cf385"
```

This creates a versioned migration chain.

# 23. Downgrade

Move back one migration:

```bash
alembic downgrade -1
```

This executed:

```python
op.drop_column('users', 'age')
```

and moved the database from:

```text
542f727d8ac1
```

back to:

```text
75285f4cf385
```

Then we restored it with:

```bash
alembic upgrade head
```

# 24. Alembic Command Cheat Sheet

| Command                                        | Purpose                                          |
| ---------------------------------------------- | ------------------------------------------------ |
| `alembic init migrations`                      | Initialize Alembic                               |
| `alembic revision -m "message"`                | Create empty migration                           |
| `alembic revision --autogenerate -m "message"` | Generate migration from model/schema differences |
| `alembic upgrade head`                         | Apply all pending migrations                     |
| `alembic upgrade +1`                           | Move forward one migration                       |
| `alembic downgrade -1`                         | Move backward one migration                      |
| `alembic current`                              | Show current DB migration                        |
| `alembic history`                              | Show migration history                           |

# 25. Important Alembic Workflow

For a normal schema change:

```text
1. Change SQLAlchemy model
          ↓
2. Generate migration
          ↓
alembic revision --autogenerate -m "..."
          ↓
3. REVIEW migration
          ↓
4. Apply migration
          ↓
alembic upgrade head
          ↓
5. Verify
          ↓
alembic current
```

Do **not** blindly trust autogenerate.

Always review the generated migration before applying it, especially for:

- Dropping columns
- Renaming columns
- Changing nullable constraints
- Changing data types
- Adding constraints
- Production data migrations

# 26. `create_all()` vs Alembic

We initially experimented with:

```python
Base.metadata.create_all(engine)
```

This creates missing tables.

However, it is **not a replacement for migrations**.

### `create_all()`

Useful for:

```text
Create database schema from scratch
```

It does not provide a versioned migration history.

### Alembic

Used for:

```text
Versioned schema changes
```

For example:

```text
v1 → create users
v2 → add age
v3 → create tasks
v4 → add priority
```

For real applications, Alembic should normally manage schema evolution.
